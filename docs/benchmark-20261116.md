# 双网直连实测（2026-11-16）

在 F50 上启动仅监听 127.0.0.1 的独立 Mihomo 实例，使用本插件 boost.rb 生成的子规则和双出口节点，不修改生产插件的 settings.json。测试域名为清华镜像站，明确 DIRECT 规则后进入范围子规则；使用 round-robin，每轮四条 TCP HTTPS Range 下载连接，合计约 15.5 MiB。两轮顺序为 Wi-Fi→移动→双网、双网→移动→Wi-Fi，测量含连接建立与 TLS 时间的总完成吞吐。

| 模式 | 第1轮 Mbps | 第2轮 Mbps |
|---|---:|---:|
| Wi-Fi | 68.32 | 61.71 |
| 移动数据 | 95.30 | 87.98 |
| 双网 | 102.54 | 77.19 |

24 条正式连接均返回 HTTP 206，所有请求成功完成。双网轮次的 Mihomo connection chains 同时包含 WDS-BOOST-WIFI 与 WDS-BOOST-MOBILE，两个接口各接收约 8–9 MB。证明连接实际同时使用两个出口，但不证明单连接叠加或稳定获得两条线路带宽之和。第二轮双网低于移动单网，说明无线/移动路径波动和固定连接分配会限制增益。样本短、同一镜像源，不能作为长期峰值或端到端客户端性能保证。

测试发现原负载均衡组使用 gstatic HTTP 204 探测时，移动节点被判不可用，导致实际全部选择 Wi-Fi。两条线路直接访问 hicloud 204 均成功，改用该地址后同时使用双网。探测点仍可能独立故障，此处修复不等于所有网络通用保证。

测试还包括两轮修复前对照和少量连通性请求。全部测试的移动下载流量约 80–90 MiB，接口统计混有后台流量，非运营商计费值。测试结束后独立核心及监听端口退出，生产状态保持 split，DIRECT=Wi-Fi、PROXY=移动，加速关闭。未关闭物理接口，未执行生产环境断网故障测试。
